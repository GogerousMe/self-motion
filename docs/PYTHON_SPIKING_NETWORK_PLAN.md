# Python 自运动神经网络主线修订（2026-11-06）

状态：Python基础组件、MT回路、细时间步连续MSTd适配、延迟反馈接口及监视器已实现。实际入口和边界见[运行说明](PYTHON_SPIKING_RUN.md)。脉冲MSTd仍未实现；此前CARLsim测试不作为本方案验收。

## 目标与取舍

主线是 Python 内存中的统一神经仿真循环，方便持续构建 V1–MT–MSTd、自运动读出及反馈。
Python 不调用 CARLsim 可执行文件，不以磁盘文件连接脑区。已有 CARLsim 桥接后端降为可选离线对照。
采用 NumPy 可读参考与可选 PyTorch 张量后端，不以每个神经元一个 Python 对象/两两遍历突触实现。
不开发完整通用仿真器：先不实现 CARLsim 的多GPU分区、全部受体、STDP/STP、网络快照和通用回调体系。
目标是机制清楚、可扩展、数值稳定；不承诺与 CARLsim 逐脉冲/逐电压完全一致。

## 首版机制

- 保留 MotionEnergyV1 图像前端。每帧产生 [3,28,H,W] 连续响应，帧区间内保持驱动。
- Python 本地可复现随机源生成 V1 泊松事件；明确时间离散、事件计数/二值脉冲约定及高率行为，不以概率截断隐蔽改变输入率。
- 通用 Izhikevich 群体维护 v/u、阈值和复位；E/I 均先用既有参数。相同群体实现可用于后续 MSTd。
- 最小电导突触只包含快速兴奋/抑制分量、指数衰减、反转电位与因果延迟。不强求复制全部 AMPA/NMDA/GABAa/GABAb 细节。
- 使用现有有符号28×8矩阵的正负分路：V1→MT-E、V1→MT-I、MT-I→MT-E。
- MT 保留 [8,H,W] 位置/方向群体；原始脉冲、滤波活动和诊断量都可以读取。
- 统一时钟例如1ms，并提供神经元积分子步设置；最终步长和增益通过收敛/刺激试验确定，不把示例值冒充已校准参数。
- 第一版不加入未经验证的MT归一化群体、空间增强或MT→V1反馈。MSTd→MT反馈接口默认零增益，反馈机制须独立设计和消融。

## 数据与模块边界

设计责任划分如下。首版实际实现集中在neural.py（基础组件）、spiking_mt.py（MT回路）、model.py（时间循环与反馈）、monitors.py（记录）；表中neural/目录为后续按规模拆分的建议，不是已存在路径：

| 模块 | 责任 | 持久状态 |
|---|---|---|
| neural/neurons.py | Izhikevich群体的同步积分/放电/复位 | v、u、必要的放电状态 |
| neural/synapses.py | 电导衰减、事件驱动、延迟缓冲 | g_exc、g_inh、延迟队列 |
| neural/encoding.py | 率到泊松事件 | 独立随机源/种子 |
| spiking_mt.py | V1→MT方向投影与E/I回路 | MT群体和通路状态 |
| neural/network.py | 统一时钟、同步调度与反馈路由 | tick、跨区延迟 |
| neural/readout.py | 因果脉冲迹、率和任务读出 | 滤波迹 |

群体输入应支持可叠加的兴奋/抑制突触驱动及明确单位的外部调制；输出包含本步脉冲。
神经元群体不应知道投影矩阵、脑区名称、磁盘路径或摄像机几何。
MT回路不应内置MSTd航向估计，也不应只提供帧末方向向量。
文件监视器是旁路：保存开关不改变随机源、神经状态和网络输出。

## 同步执行和反馈

每个细时间步：

1. 读取已到达的前馈/反馈事件及本区历史状态。
2. 衰减并更新各区突触状态。
3. 从该时间步的输入同步推进所有神经元群体，产生新脉冲。
4. 将新脉冲调度到未来的延迟队列，更新因果活动迹，再进行可选记录。

必须明确时间戳为步起点或步终点，保持最小因果延迟，不因先调用MT还是MSTd改变结果。
图像帧与神经时钟解耦，例如50ms图像间隔内部推进50个1ms步。整帧末才交换一次数据不满足本主线的反馈目标。
独立序列才reset；帧间、方向切换和短暂静默保留状态。

阶段一以临时适配器连接当前连续TensorMSTd：在细时间步使用因果MT活动更新，作为过渡闭环；这仍然是混合模型。
阶段二将MSTd模板/连接及竞争机制映射到同一套Python神经元/突触群体。原模板匹配器不应直接更名为脉冲MSTd。
反馈通道从阶段一就支持，但反馈选择性、符号、增益和科学依据单独验证；存在接口不等于已经实现有效反馈。

## 连接与性能

局部V1→MT连接通过通道张量收缩计算，E/I通路分别保留；不构造全局N×M候选矩阵。
共享时常数的指数突触可按接收神经元汇总电导，不必为每条固定突触保存独立状态。
这可避开旧CARLsim逐候选构网，但不能据此预报运行FPS。Python循环只遍历时间步/少数群体，空间和通道运算向量化。
后续MSTd使用明确的方向/位置到模板群体的连接；反馈连接单独定义，不默认声称前馈权重转置就是生物反馈。

## 必须验证

1. 单神经元恒流/零驱动的电压、复位、适应及数值稳定；时间步减半和积分子步收敛。
2. 单事件突触响应的幅值、指数衰减、反转电位、延迟；不得提前到达。
3. 泊松多种子计数均值/方差、零输入和高率行为；固定种子的重置/重放。
4. 小网连接的方向/位置/符号、E/I消融、无空间串扰、跨帧状态和切换延迟。
5. 同步调度对脑区调用顺序不敏感；已知延迟的人工反馈回路按预期影响MT；关闭反馈恢复前馈结果。
6. 监视器开关不改变输出；CPU参考与可用PyTorch后端作容差/统计对照。
7. 八方向光栅/随机纹理、多速度、停止/切换；再评估纯平移航向及动态干扰。机制检查与任务精度分别验收。
8. 初始化、仿真、读出与存储分项计时，测内存/显存；不沿用旧166.6s构网数据评价新后端。

基础组件、MT、过渡MSTd与反馈接口已有独立测试和图像检查；结果记录见PYTHON_SPIKING_VALIDATION.md。脉冲MSTd、有依据的反馈机制及自运动精度仍待研究，不能使用此前CARLsim CPU测试替代。
