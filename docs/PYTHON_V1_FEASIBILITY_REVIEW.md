## 1. 结论

可以脱离 CARLsim，在本项目中用 Python 实现从图像刺激到 V1、MT、MSTd 的完整计算链路。优先方案是迁移实际实验版本的 MotionEnergy 数值计算，接入已验证的 Python MT；保留可选脉冲编码用于历史实验对照。

需要分别定义三个目标：

1. **迁移一致性**：Python V1 是否复现实际运行的 C++/CUDA V1 连续响应。
2. **任务有效性**：新前端连接现有 MT 后，方向调谐、空间响应、时间响应和 MSTd 航向是否通过实验。
3. **文献复现**：是否逐式实现某一篇论文。相同脑区名称、相同输出维度或相似方向调谐，都不足以证明公式一致。

用户已报告真实 CARLsim V1 -> Python MT 实验正确，应作为后续回归基线。此次未取得该最新实验的完整采集包，不能将本地单元测试表述为独立复现了该实验。

## 2. 当前项目的实际内容和目标

已检查 `src/mstd/{carlsim,projection,mt,mstd,data,io,calibration,selfmotion,cli}.py`、相关测试、配置与技术文档。

当前计算链路：

```text
图像刺激 DAT
  -> 外部 C++/CUDA MotionEnergy
  -> CARLsim V1 脉冲 DAT
  -> Python 按时间窗计数并转为 Hz
  -> 28 类时空滤波器 × 3 尺度 -> 8 个方向
  -> MT 局部空间平均与方向归一化
  -> MSTd 径向膨胀模板、时间竞争
  -> 平移方向、有效性和群体活动
```

输入刺激 DAT 与 SpikeMonitor 输出 DAT 是不同格式，不能互换。

| 部分 | 当前源码中的实现 | 对目标的意义 |
| --- | --- | --- |
| V1 接口 | 84 通道脉冲读入；显式 28×8 有符号投影，三尺度加权汇总后整流 | 已有可复用的前后端分界 |
| MT | 默认 3×3 邻域平均；每像素跨方向除法归一化；输出方向群体向量及可选空间活动 | 局部运动方向证据 |
| MSTd | 不同膨胀中心的方向模板匹配，加简化循环竞争 | 纯平移航向参考基线 |
| 当前读出 | CLI 默认水平 -20° 到 +20°，5°间隔 | 相机坐标中的平移投影方位角 |
| 长期目标 | 扩展后退、旋转、曲线路径、动态干扰，再研究与几何/IMU/轮速及 SLAM 连接 | 尚需后续模型与任务验证 |

`encode_mt()` 的归一化在数学上等价于 `pooled[d] / (1 + sum_d pooled[d])`，实现通过先缩放避免溢出。此处的 MT 向量幅值是方向证据，当前不能直接作为像素速度或米制速度。

`MSTd.step()` 有时间状态；当前 MT 编码本身没有膜电位或独立的时间积分状态。现有 MSTd 方程为 CD 启发的工程简化式，源文件明确声明并非原论文复现。

现有脉冲适配器使用带负权的线性投影及整流，不等价于旧 CARLsim MT 兴奋/抑制脉冲网络的完整动力学。

## 3. CARLsim 中的 V1 到底是什么

直接证据位于：

- `projects/v1mt_wyq/src/main_v1toCDS1.cpp:365`：V1 网格深度为 `28*3`。
- 同文件 `:373`：`createSpikeGeneratorGroup("V1", ...)`。
- 同文件 `:466`：`me.calcV1complex(...)` 写入 PoissonRate 的率数组。
- 同文件 `:467`：`sim.setSpikeRate(gV1, &rateV1)`。
- 同文件 `:469`：每帧推进神经仿真时间。
- 同文件 `:379`：Izhikevich 参数设置针对 MT。

因此这一路径的 V1 是“运动能量计算 + 率驱动的脉冲生成群体”，没有为 V1 构建 Izhikevich 膜电位网络。需要迁移的主要工作是前端时空计算，而非重写整个 CARLsim 仿真器。

概念上可分成：

```text
V1 连续响应 = MotionEnergy(图像及历史)
V1 脉冲事件 = 脉冲编码器(V1 连续响应、仿真时间、随机数)
```

28 个通道代表 x/y/t 时空滤波朝向，不是均匀分布的 28 个图像运动方向。三个尺度通过逐级时空平滑构造，不能直接命名为三个已标定的速度偏好。

源码保留 speed 参数的取值断言，但在直接输出 84 通道、绕过 `calcV1direction(speed)` 的路径中，它不负责选择八方向投影。因此 speed 参数本身也不能充当这 84 通道的速度标签。

## 6. 推荐迁移架构

```text
原始图像 DAT / 解码后图像帧
  -> Python MotionEnergy V1
       灰度规则、帧缓存、三尺度时空滤波、28朝向
       边界抑制、平方非线性、可配置空间池化、归一化
  -> 连续响应 R[scale, filter, y, x]
       |-> 兼容路径：CARLsim式离散脉冲采样 -> 同一时间窗计数
       |-> 直接路径：使用连续响应
  -> 同一套有符号28×8投影、尺度汇总和整流
  -> 现有 V1Frame / 方向率协议
  -> 现有 encode_mt()
  -> 现有 MSTd.step()
```

优先用 NumPy 建立可核对的 CPU 参考实现；性能实测后，再考虑 PyTorch GPU 后端。这里的 Python 指数值模型的开发与调度，不要求把卷积写成逐像素 Python 循环，也不要求用数据训练一个替代 V1 的神经网络。

原工程已经有 `external/MotionEnergy/pyME`。但其 `motionenergy.py` 使用 PyCUDA、旧式导入与 `xrange`，调用八方向投影，complex 默认增益为0.99，和本地25增益及84通道路径不同。它可作算法交叉参考，不能直接当成当前实验的 Python 等价物。

### 连续率与脉冲兼容需要分别验收

CARLsim CPU/GPU 的 `getPoissonSpike()` 均比较 `uniform_random * 1000 < rate`。与连续时间 Poisson 过程、每窗直接抽取 Poisson 计数，存在离散时间语义差别；若需与历史脉冲统计对齐，要核对实际时间步、采样机制及高放电率饱和。

当前有符号投影之后会整流，因此通常有：

```text
E[relu(W * spike_rate)] != relu(W * E[spike_rate])
```

后续 MT 归一化也是非线性的。直接去掉脉冲采样可以减少一类随机波动，但不保证与某次历史 MT 图逐像素相同，也不自动保证平均输出无偏。先在连续84通道层验证数值迁移，再用多随机种子检验脉冲统计和 MT 结果，能分开定位误差来源。

为了方便审计，可以新增连续响应接口和方向投影适配器。现有 `project_counts()` 按脉冲计数及毫秒换算率，不能将浮点率直接作为 count 传入，否则会重复乘以 `1000/bin_ms`。

V1 原始布局与神经元编号应保持：

```text
pixel = y*W+x
neuron_id = ((scale*28 + filter)*H + y)*W + x
```

从直接84通道路径接入时，Python只做一次方向投影；不能先输出八方向又套用28×8矩阵。独立序列 reset，连续运动切换保留历史。启动、滤波群延迟、采样窗可用时刻和最后静默时间段都需要记录。

## 7. 分阶段实施与通过条件

| 阶段 | 工作 | 交付与判据 |
| --- | --- | --- |
| P0 固定实验基准 | 保存成功实验入口、实际链接库、刺激、配置、源代码及SHA256 | 明确池化、边界补偿、历史缓存和通道布局，能够重放原结果 |
| P1 连续响应基准 | 在实际C++库的泊松采样之前导出连续84通道，必要时导出线性、平方、归一化各阶段 | 同一刺激的逐帧浮点参考；只需短序列，不必先导出长实验 |
| P2 Python V1 | 实现与基准相同的数值运算和状态 | 分阶段RMSE/最大误差、逐通道曲线、边界与延迟；事先按参考量级和float32舍入设容差 |
| P3 MT回归 | 固定现有投影和MT参数，比较连续与脉冲兼容两路径 | 八方向、静态/黑场、速度范围、空间图及切换响应；脉冲路径统计多次随机运行 |
| P4 MSTd端到端 | 静态点云、前进、固定朝向的左右斜向平移，使用已知内参和真值 | 航向误差、有效覆盖率、静止误报、启动/切换延迟 |
| P5 扩展机制 | 按实验需要增加速度表征、反馈、收缩/旋转/地面模板及动态物体 | 每项与当前冻结基线对照；再进入曲率、转向和位姿融合 |

P2 的数值对照不要只看相关系数；高相关也可能有错误增益、符号或时间偏移。先固定真实时序，测量并报告延迟，不能通过任意平移曲线掩盖实现差异。

建议第一批短刺激包含：静态纹理、黑场、可定位的脉冲/点、八方向移动光栅与随机纹理、至少数个速度、方向切换和运动后黑场。光栅和纹理共同使用，以免单一条纹掩盖孔径歧义。
