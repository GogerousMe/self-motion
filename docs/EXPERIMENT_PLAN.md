# V1–MT–MSTd 测试实验需求与实施方案

日期：2026-10-19

适用项目：`D:\A_Gorger\program\MSTD\code`
执行方式：Linux 手动运行现有 C++ V1；将真实响应返回 Python 项目分析。

## 1. 实验目的与当前边界

本方案要依次回答四个问题：

1. 修改版 V1 的响应能否正确转换为 MT 的八方向运动证据？
2. MT–MSTd 能否根据全局光流估计相机的平移航向？
3. 时间竞争能否在动态干扰下改善准确性和稳定性，且不会造成不可接受的延迟？
4. 何时需要增加速度通道、多模式模板、群体解码或学习型 MST？

当前已有：V1 SpikeMonitor DAT 读取、84 通道到八方向的投影、MT 局部池化与归一化、径向扩张模板、简化时间竞争以及水平航向读出。

当前默认航向模板：−20°～20°，间隔 5°。当前尚未实现：收缩／旋转／螺旋等完整模板群体、曲率解码、原 CD 逐式复现、MT–MSTd 反馈和 STDP 后端。

**代码与文件格式测试通过，不代表真实 V1→MT→MSTd 的任务准确率已经通过。当前首要任务是采集新刺激的真实响应。**

本阶段不以完整位姿、长期轨迹或绝对速度为验收目标；静止及纯旋转条件下，平移航向没有定义。

## 2. 总体顺序与职责

```text
A：八方向校准 → 判断 V1→MT 编码是否正确
                    ↓
B0：理想运动证据 → 独立检查 MT–MSTd 后端
B1：真实 V1 响应 → 建立纯平移端到端基线
                    ↓
C：动态干扰＋真实航向变化 → 比较竞争、普通平滑与瞬时匹配
                    ↓
D：后退／旋转／曲线路径 → 多模式模板和参数解码
                    ↓
E：与 C++ STDP 网络作同输入、同任务对照
```

- Linux 采集：播放指定刺激，启用 V1 脉冲监视，独立保存各条件响应与运行信息。
- Python 分析：检查文件与配对关系，投影 MT 响应，运行后端，输出调谐、航向及时间指标。
- 模型修改：根据每一轮的诊断结果实施，不同时修改多层后直接比较总误差。

B0 可与 Linux 采集并行进行。A 未通过时，可以诊断 B1，但不能将错误结果直接归因于 MSTd。

## 3. 通用刺激和采集要求

### 3.1 现有刺激的默认参数

| 参数 | 当前设置 |
|---|---|
| 图像大小 | 80 × 80，单通道灰度 |
| 序列长度 | 80 帧 |
| 每帧仿真时间 | 50 ms，即 20 fps |
| 总刺激时长 | 4000 ms |
| 初始预热设置 | 前 20 帧，即 1000 ms；需检查是否足够 |
| 方向校准速度 | 1.5 像素／帧 |
| 自运动前进速度 | 3 m/s，静态和纯旋转条件除外 |
| 自运动水平视场 | 90° |
| 自运动相机内参 | fx=fy=40 px，cx=cy=39.5 px |
| 自运动场景 | 250 个随机点，深度范围 2～50 m |
| 地面条件相机高度 | 1.61 m |

方向校准的像素速度和自运动的米制相机速度不是同一个量，不能直接互换。所有新条件以其实际清单和真值为准。

### 3.2 坐标与输入格式

- Python 图像坐标：x 向右、y 向下，方向角顺时针增加。
- 八方向：0°右、45°右下、90°下、135°左下、180°左、225°左上、270°上、315°右上。
- 原 MATLAB 光栅流程含 `flipud`，与新刺激的方向约定不同；换算为 `theta_python = (-theta_matlab) % 360`，并用实际像素运动复核。
- 自运动航向：相机坐标下右偏为正，左偏为负；相机姿态角与平移航向必须分开记录。
- 优先使用已有刺激 DAT 直接送入 VisualStimulus。这里的刺激 DAT 是图像帧文件，**与输出的 `spk_V1.dat` 脉冲事件文件格式不同**。
- MP4 用于查看。若经视频解码后输入，需记录帧率、尺寸、缩放、翻转与转码设置，并确认最终帧与真值一致。
- 不以论文中的光流箭头图作为输入刺激；V1 应接收实际点阵／纹理图像序列。

### 3.3 Linux 运行要求

1. 每个独立条件启动独立运行，重置 V1 历史；连续动态序列内部则不得逐帧重置。
2. 确认实际编译入口、加载的网络快照和链接的修改版 MotionEnergy 库，而不只检查源码目录。
3. 确认 V1 群体深度为 84，即 28 类滤波器 × 3 个尺度。28 类滤波器不是均匀的 28 个图像方向。
4. 启用 V1 SpikeMonitor，不能只返回 MT 监视文件。
5. 完整读取 80 帧，核对每帧 50 ms，避免历史帧数常量截断。
6. 每个条件使用唯一输出目录，避免覆盖或误用旧响应。
7. 明确记录完整仿真时长。最后一次脉冲的时间不等于仿真结束时间，静默区间也必须保留。

**可以完全沿用手动采集方式，不要求使用批量脚本或环境变量接口。** 可选自动化接入见 [CALIBRATION.md](CALIBRATION.md)。

## 4. 第一轮 A：V1→MT 八方向校准

### 4.1 目标与输入

目标：确认通道含义、方向符号、八方向可区分性及背景响应。

| 编号 | 输入刺激 | 条件数量 | 状态与用途 |
|---|---|---:|---|
| A1 | 平移随机亮点纹理，八方向，1.5 px/frame | 8 | 已生成；第一批优先采集 |
| A2 | 移动正弦光栅，八方向，周期 12 px | 8 | 已生成；补充检查空间频率与孔径影响 |
| A3 | 与运动纹理配对的静态纹理 | 1 或多个种子 | 待补充；检查启动与背景活动 |
| A4 | 同类纹理的多速度条件 | 后续确定 | 待补充；基线后增加，如 0.5、1、2 px/frame |

现有目录：`outputs/calibration_texture_01/`、`outputs/calibration_grating_01/`。
现有打包文件：`outputs/calibration_bundle_01.tar.gz`。

### 4.2 分析要求

- 初始分析排除前 20 帧，并画出全程时间曲线，以检查预热是否足够。
- 默认排除 4 像素边界；所有对照固定相同的 ROI 与时间窗。
- 每个时间窗先进行方向投影和整流，再汇总；不要把原始响应平均后才投影整流。
- 输出八通道平均响应、84 通道平均活动、胜出方向、环形方向误差和方向集中度。
- 补充逐窗结果，以免均值掩盖持续切换或早期错误。
- 至少将一种投影配置作为预先固定的基线；比较其他矩阵时记录配置，不能根据测试标签逐条挑选最有利矩阵。

### 4.3 判据与下一步

当前校准工具已有的初始工程判据：八方向齐全、各方向有响应、方向集中度 ≥0.1、胜出方向误差 ≤22.5°。这些不是行业或生物学标准，也不等于自运动航向通过。

| 实验现象 | 诊断与后续工作 |
|---|---|
| 八方向整体旋转、镜像或相反 | 优先修复通道、坐标、投影符号与翻转 |
| 多个输入方向都激活同一输出方向 | 检查滤波器编号、投影矩阵索引、增益和真实链接库 |
| 纹理通过，光栅不稳定 | 检查空间频率、孔径歧义及池化；不能立刻判断整条链路失效 |
| 静态持续产生强运动证据 | 检查启动响应、背景放电、投影偏差及有效门限 |
| 基线速度通过，其他速度失效 | 标定速度适用范围，再决定是否增加速度通道 |

单通道以外的神经元也可响应；判据关注方向可区分性，不要求理想独热输出。

## 5. 第二轮 B：纯平移航向基线

### 5.1 B0：独立检查后端

以已知相机运动产生的理想方向群体响应输入当前 MT–MSTd，排除 V1 编码误差。输入必须采用当前接口的方向响应语义，不能把未经处理的 px/frame 光流直接当作活动率。

先测试 0°、±10°；随后测试 ±7°、±13° 等模板网格外航向。检查模板中心、角度映射、匹配分数和竞争输出。

如果 B0 错误，先修复后端；B0 正确但 B1 错误，重点检查真实前端。理想响应只用于诊断，不能替代端到端测试。

### 5.2 B1：已有五条件真实 V1 采集

| 条件名 | 输入内容 | 预期与目标 |
|---|---|---|
| `cloud_static` | 静态三维点云，相机不动 | 预热后尽量不输出有效运动航向；航向真值为空 |
| `cloud_forward` | 静态三维点云，相机正前进 | 航向接近 0°；检查完整视场扩张 |
| `ground_forward` | 静态地面点，相机正前进 | 航向接近 0°；检查下半视野条件 |
| `ground_heading_left10` | 朝向固定，平移速度向左偏 10° | 航向接近 −10° |
| `ground_heading_right10` | 朝向固定，平移速度向右偏 10° | 航向接近 ＋10° |

现有目录：`outputs/selfmotion_01/`；第一批包：`outputs/selfmotion_baseline_01.tar.gz`。
参数与真值见配套 `manifest.json`、`intrinsics.json`、`*.truth.jsonl`。

**斜向平移不是转弯。** 本轮左右条件保持相机朝向固定，不能解释为左转／右转识别。

### 5.3 扩展条件与重复

- 五条件完成后，增加 ±7°、±13° 等网格外航向，避免只测模板中心。
- 初步筛查建议每个随机场景条件使用至少 3 个种子；正式验收扩大独立场景数量并报告不确定性。
- 重复相同视频可估计神经仿真的运行随机性，但不等于增加独立场景数量；分别记录场景种子和模型随机种子。
- 需要调门限或参数时，将完整序列分为开发／验证／测试组；禁止随机拆分相邻帧。

### 5.4 必须报告的指标

| 指标 | 定义与注意事项 |
|---|---|
| MAE | 有定义且输出有效的帧上，估计航向与真值的平均绝对角度误差 |
| Bias | 同一条件下的平均有符号误差，识别系统性偏左／偏右 |
| P95 | 绝对误差的第 95 百分位数 |
| 输出波动 | 恒定航向下，稳态输出随时间的变化；应结合误差一起解释 |
| 有效覆盖率 | 航向有定义的评估帧中，输出有效的比例 |
| 静态误报率 | 静止评估帧中，错误输出有效航向的比例；不计算静态角度误差 |
| 收敛与跟踪时间 | 按预先固定的容差与持续时间，测量启动收敛／真实变化后的响应延迟 |

使用适合角度的环形误差；当前有限水平范围中与普通差值通常一致。先按序列计算，再汇总独立序列，不能把同一序列的相关帧当作独立重复。

同时报告启动段和预先固定的稳态段。不得逐条选择“看起来最好”的时间区间，也不能只报告最后一帧。

### 5.5 结果到开发决策

| 结果 | 下一步开发 |
|---|---|
| 理想输入也错误 | 检查相机内参、模板几何、坐标、匹配、积分及竞争参数 |
| 理想输入正确，真实响应错误 | 检查方向投影、局部方向场、时间与前端滤波延迟 |
| 点云正确，地面明显偏差 | 检查弱响应区、地平线、空间权重与有效区域 |
| 结果基本正确，但呈 5°台阶 | 比较更密模板与峰值插值，报告计算代价 |
| 持续停在 ±20°边界 | 排查偏置与覆盖范围；不能把边界输出直接当作准确估计 |
| 提高门限后 MAE 降低，但覆盖率很低 | 检查证据不足；不以拒绝大量样本代替性能提升 |

当前没有足够真实响应支持最终 MAE、覆盖率和延迟阈值。第一批开发数据用于确定工程阈值，须在独立测试前记录并冻结；不能套用论文精度作为本项目通过标准。

## 6. 第三轮 C：时间竞争与动态干扰实验

本轮刺激和自动评价尚需开发，不能把现有视频生成器误认为已有动态物体模块。

### 6.1 输入条件

| 输入 | 控制与变化 | 目的 |
|---|---|---|
| 静态背景自运动＋独立运动物体 | 先比较无物体／有物体，再变化物体位置、方向和图像占比 | 测动态证据的干扰 |
| 相同背景＋遮挡区域 | 与动态物体使用尽量匹配的覆盖区域 | 区分遮挡损失和错误运动证据 |
| 随机方向噪声或对比度变化 | 各强度固定种子，对照相同背景 | 测噪声与弱运动证据影响 |
| 真正改变平移航向的连续序列 | 固定相机朝向，改变速度方向 | 测跟踪延迟，防止把迟钝当作稳定 |

### 6.2 同输入对照

1. 瞬时模板匹配，无时间状态。
2. 模板匹配＋普通指数时间平滑。
3. 模板匹配＋当前竞争动力学。
4. 后续可增加原 CD 动力学作为独立版本。

使用相同 MT 输入、模板、评价时间段和划分。普通平滑也应合理调参；比较相近延迟下的误差，或报告误差—延迟关系，而不只选一个任意平滑参数。

除 B 轮指标外，增加干扰引入的额外偏差、遮挡结束后的恢复时间、真实航向改变后的跟踪延迟。

| 结果 | 决策 |
|---|---|
| 竞争降低误差和波动，延迟可接受 | 保留机制，扩大独立场景评估 |
| 与普通平滑相近 | 暂不声称竞争有额外收益；检查参数和原 CD 机制 |
| 输出平稳但明显滞后或锁定旧航向 | 调整时间常数、自激励、抑制，重新测真实变化 |
| 大型持续动态物体下失效 | 研究空间加权、更完整竞争或反馈；根据证据再考虑物体分支 |

## 7. 第四轮 D：运动类型与曲线参数扩展

只有平移基线稳定后，才开展本轮的任务验收。已有部分视频可以用于观察模型失效，但当前径向输出不能作为这些功能已实现的证明。

| 输入条件 | 已有例子／状态 | 对应开发与目标 |
|---|---|---|
| 后退 | `cloud_backward`，已有 | 增加收缩模式；后退方向不能记成前进 0° |
| 位置固定、纯左右 yaw | `ground_yaw_left/right`，已有 | 研究旋转响应；平移航向为空，不纳入普通航向 MAE |
| 左右圆弧、相同半径 | `ground_turn_left/right_r45`，已有 | 增加多模式群体与转向读出 |
| 相同转向、不同半径 | 右转 R20／R45／R85，已有 | 建立曲率读出，检查未见曲率泛化 |
| 相同路径、不同视线偏角 | R45 右转、偏角 ±20°，已有 | 估计视线相对轨迹切线偏角，避免与曲率混淆 |
| 平移／旋转组合及未见参数 | 需要扩展 | 分离运动因素，检查跨速度、曲率、场景泛化 |

开发路线：多模式 MSTd 表征 → 保留群体活动 → 线性／小型网络参数读出 → 如有证据需要额外记忆，再比较 ESN。

新增指标：转向分类混淆矩阵及 F1、曲率 MAE、视线偏角误差、变化跟踪延迟。米制曲率依赖已知高度、场景约束或其他尺度来源，应显式记录。

圆周／螺旋模板不是车辆 yaw／左右转的直接标签；图像中心旋转主要模拟 roll，不能替代车辆平面转弯。

## 8. 与 C++ STDP 模型的公平对照 E

- 先明确原 784 维 CSV 的编码含义；不得任意将多方向 MT 响应压缩成 784 维后直接比较。
- 两条路线使用语义一致的输入、相同训练／验证／测试序列及相同运动真值。
- 为 STDP MST 增加明确的航向或参数读出；记录训练数据量、神经元规模、运行时间和参数搜索预算。
- 测试阶段固定权重和读出，避免利用测试序列标签调参。
- 同时报出重建相关性与自运动任务误差；二者不能互相替代。
- 若比较脉冲与活动率机制，应说明泊松随机性及 500 ms 样本窗口与连续帧窗口的区别，避免将不同时间预算的结果混为一谈。

## 9. 每次采集应保存与返回什么

推荐布局；手动方式不必严格照搬目录，但必须保留对应关系：

```text
experiment_001/
  experiment_notes.md
  manifest.json                 # 若使用已有刺激清单，保留原件
  intrinsics.json               # 自运动条件需要
  responses/
    texture_dir000_seed001/
      spk_V1.dat
      run_config.txt
      process.log
    cloud_forward_seed001/
      spk_V1.dat
      run_config.txt
      process.log
```

最低必需信息：

- 条件名、输入文件名、输入文件校验值或可核对的原始文件。
- 对应 `spk_V1.dat`；不能把所有结果都命名相同后混放在同一目录。
- 实际图像宽高、通道数、帧数、每帧仿真时长、完整仿真时长。
- V1 群体维度、通道顺序与实际输入预处理。
- 使用的代码版本、可执行程序、MotionEnergy 库、网络快照及关键参数；能记录 SHA256 时一并记录。
- 场景种子、神经仿真种子（如果可设）；无法确认的值注明未知。
- 自运动输入配套的内参与逐帧真值。
